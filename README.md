# Do LLMs Feel Electric Emotions? The Geometry of Affect Across AI-centric and User-centric Scenarios

Code and data for the paper. We train linear probes that decode the emotional
tone of a model's response from its hidden states, and ask if the representations are different based on the psychological taxonomy used to label the
responses, the kind of stimulus the model reads, and the position in the
forward pass where the activation is read.

## Overview

- **Stimuli.** Three domains are generated by one pipeline from the same 145
  emotion concepts (Shaver et al., 1987), with Wikipedia noise injection for
  diversity:
  - *AI-centric*: situations about the model's own deployment, addressed to it.
  - *Human 3rd-person*: vignettes about people unrelated to the model.
  - *Human conversational*: a user sharing a situation from their own life.

  The three corpora hold about 65k prompts, written by Claude Opus 4,
  Gemini 2.5 Pro and Grok 4.
- **Models.** Seven open-weight chat models: Llama-2-7b-chat-hf,
  Llama-3.1-8B-Instruct, Qwen2.5-14B-Instruct, Qwen3-14B, GLM-4-32B,
  gemma-4-12b-it and Qwen3.6-27B.
- **Annotation.** GPT-5-mini labels every response under three taxonomies:
  Ekman, Plutchik and GoEmotions. The judge was chosen after calibration against
  expert annotations and a panel of seven LLM annotators.
- **Analysis.** Per-layer logistic-regression probes read at the prompt's last
  token and at the generated response's last token, scored by chance-corrected
  macro-F1. Probes are also compared through the cosine similarity of their
  weights, and hidden-states through representational similarity analysis (RSA).

**Findings.** Ekman, Plutchik and GoEmotions probes
recover similar directions. The stimulus domain and the read-out position are key in the design of the probes. At the prompt, probes trained on different domains are near-orthogonal.
After generation, they move closer together.

## Setup

1. **Python environment** (Python 3.11):
   ```bash
   python -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
   `requirements.txt` pins the environment of the inference runs
   (vLLM 0.22.1, PyTorch 2.11, CUDA 13).

2. **API keys.** Stimulus generation and the calibration panel use OpenRouter,
   and the judge uses the OpenAI Batch API:
   ```bash
   cp .env.example .env   # then fill in OPENROUTER_API_KEY and OPENAI_API_KEY
   ```

3. **Hardware.** Inference and activation capture run on GPUs through vLLM; use
   `--tp` to split large models across devices. The analyses of the included
   result files run on a CPU.

Run every command from the repository root.

## Reproducing the results

The pipeline has five stages:

1. Generate the stimuli: `src/llm/generate_prompts.py`
2. Run the target models and capture the activations:
   `src/llm/generate_with_hooks.py`, then `scripts/output_and_activation_pairing.py`
3. Annotate the responses with the judge: `src/nlp/responses_annotation.py`,
   then `scripts/annotations_and_activations_merge.py`
4. Train the probes and the shuffled-label controls:
   `src/probes/train_linear_probes_on_annotations.py`
5. Analyze: RSA (`src/probes/RSA_multilabel.py`) and probe-weight cosines
   (`src/probes/features_heatmap.py`, `src/probes/interdataset_features_heatmap.py`)

The CSVs behind the paper's figures and tables are included. To redraw the
taxonomy-analysis figures from them, with no GPU needed:

```bash
python src/probes/paper_figures.py
```

Model responses, full-corpus annotations and activations are not included
because of their size. [REPRODUCIBILITY.md](REPRODUCIBILITY.md) gives the
commands and configuration of each stage, the judge calibration and the
stimulus checks, and maps each result file to the paper.
